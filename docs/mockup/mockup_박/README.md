### 2.1 컬러

| 역할 | 라이트 | 다크 | 비고 |
| --- | --- | --- | --- |

| 흐린 `--ink-3` | `#8B95A1` | `#8B95A1` | 캡션 전용 |

뉴트럴은 토스 TDS의 grey 램프를 그대로 썼다. 파랑 쪽으로 살짝 기운 쿨그레이라
파랑 액센트와 같은 계열로 붙고, 명도 간격이 균일해 표·구분선 단계를 만들기 쉽다.

각 상태색은 **마크용(`--safe`)과 텍스트용(`--safe-ink`)을 분리**했다.
노랑·주황은 흰 배경에서 텍스트 대비가 3:1도 안 나오기 때문에, 뱃지 글자에는 항상 `-ink` 쪽을 쓴다.

### 2.2 왜 브랜드 액센트가 파랑인가

화면구성도 6.1이 **초록을 `SAFE`(안전) 등급에 예약**해 두었다.
뱅크샐러드처럼 초록(`#04C584`)을 브랜드색으로 쓰면 "브랜드 강조"와 "안전 등급"이
같은 색을 놓고 싸우게 되고, 사용자는 초록 버튼을 보고 "안전하다는 뜻인가?"를 한 번 더 생각한다.

그래서 브랜드는 파랑 하나로 고정하고, 초록·노랑·주황·빨강 네 색은 **위험 등급 전용**으로 남겼다.
버튼·활성 탭·링크·선택 상태에는 이 네 색을 쓰지 않는다.
"잔고예보"라는 이름과도 맞는다(기상 예보의 파랑).

입금·출금 색도 여기서 갈린다. 한국 가계부는 출금에 빨강을 쓰는 곳이 많지만
빨강이 `GAP` 전용이라 **입금 = 브랜드 파랑, 출금 = 본문 검정**으로 잡았다(뱅크샐러드와 같은 방식).

### 2.3 타이포

```
--font-ui:   "Pretendard Variable", Pretendard, "Noto Sans KR",
             -apple-system, "Apple SD Gothic Neo", "Malgun Gothic", system-ui, sans-serif
--font-mono: "JetBrains Mono", ui-monospace, SFMono-Regular, Menlo, Consolas, monospace
```

- **Pretendard 우선, Noto Sans KR 폴백.** Pretendard는 구글 폰트에 없어서 웹폰트로 링크할 수 없다.
  목업에서는 로컬에 깔려 있으면 쓰고, 없으면 구글 폰트의 Noto Sans KR을 받는다.
  FE 착수 시에는 Pretendard Variable을 self-host 하거나 dynamic subset CDN을 쓰는 쪽을 권한다.
- **금액은 전부 `font-variant-numeric: tabular-nums` + 자간 -0.025em.**
  표에서 자릿수가 세로로 맞고, 큰 숫자가 뭉치지 않는다.
- **화면 ID·API 참조·계좌번호·날짜만 모노스페이스.** 장식이 아니라 "기계가 읽는 값"이라는 표시.
- 아이콘은 **Material Symbols Rounded**(구글 폰트, 실제 사용하는 53개만 서브셋).
  SVG를 직접 그리지 않았다. 아이콘을 추가하면 `icon_names=` 목록에도 넣어야 한다.

## 3. 뱅크샐러드 · 토스에서 가져온 것과 다르게 한 것

**가져온 것**

- 쿨그레이 캔버스 위 흰 카드, 카드 사이는 여백으로만 구분 (뱅크샐러드 홈·가계부)
- 화면당 주인공 숫자 하나를 크게 (24~30px, weight 800) — 나머지는 12~14px로 확실히 낮춤
- 하단 5탭 + 중앙 강조 액션. 뱅크샐러드는 5개 탭이 모두 화면이지만,
  우리는 가운데를 **촬영 FAB**으로 바꿨다(모바일 최빈 행동이 영수증 촬영이라서)
- 필터·상태 표시는 pill 칩. 활성 칩은 검정 채움 (뱅크샐러드 카테고리 칩)
- PC는 좌측 LNB + 상단 GNB + 우측 상세 패널 (토스증권 웹)
- 근거 문장을 숫자 옆에 붙이는 습관 ("평균보다 12% 저렴해요" → 우리는 "적요 '우아한형제들'은 …")

**다르게 한 것**

| 항목 | 뱅크샐러드/토스 | 잔고예보 |
| --- | --- | --- |
| 브랜드색 | 초록 `#04C584` / 파랑 `#3182F6` | 파랑 `#2B5CE0` — 초록은 SAFE 예약 (2.2 참조) |
| 카드 반경 | 뱅크샐러드 웹은 2px, 앱은 20px대 | 16px 하나로 통일 |
| 정보 밀도 | 뱅크샐러드는 "스크롤 없이 많이" | 매장에서 3초 안에 읽는 게 목적이라 첫 화면은 6카드로 제한 |
| 성격 | 소비 회고 (지난 달 얼마 썼나) | 미래 예보 (앞으로 언제 비나) — 그래서 첫 화면 주인공이 "지금 쓸 수 있는 돈"과 공백일 |

**차트 원칙** — 잔액 곡선은 세로축 하나만 쓴다(잔액과 입출금액을 이중 축으로 겹치지 않는다).
예측이라 점 하나 대신 변동 범위 밴드를 뒤에 깔고, 시간이 갈수록 넓어진다.
시나리오 비교는 계열이 둘(원본 회색 점선 / 변경 파랑 실선)이라 범례와 직접 라벨을 모두 붙였다.
리포트의 카테고리 막대는 길이가 크기를 말하므로 색은 한 가지만 쓴다.
적중률·단가 추이는 계열이 하나라 범례를 두지 않고 카드 제목이 계열 이름 역할을 하며,
다섯 점 전부에 숫자를 찍지 않고 시작점과 끝점만 직접 라벨을 붙였다.
품목 표의 스파크라인은 축도 라벨도 없는 보조 도형이고, 숫자는 표에 그대로 적는다.

## 6. FE 착수 시

1. **토큰 먼저 옮긴다.** `jango-yebo-mockup.html` 상단 `:root` 블록이
   그대로 `tokens.css`(또는 Tailwind `@theme`)가 된다.
   라이트 / 다크 / 시스템 3가지 상태를 모두 정의해 둔 구조를 유지할 것.
2. **컴포넌트 경계는 목업의 클래스와 거의 1:1.**
   `card` `badge` `chip` `btn` `kpi` `tbl` `gauge` `sheet` `mtabs` `lnb` `gnb` `cal` `chart`
3. **명시도 함정 하나를 기록해 둔다.**
   하단 탭의 "촬영" 라벨을 `.mtabs .fabw span`(0,2,1)으로 잡으면
   `.fabw` 안쪽 아이콘까지 함께 걸려 `.ms.s26`(0,2,0)과 `.mtabs .fab`(0,2,0)을 이겨 버린다.
   그 결과 26px 흰 아이콘이 10.5px 회색으로 렌더링된다.
   목업에서는 `.mtabs .fabw > span:last-child`로 라벨만 겨냥해 고쳤다.
   컴포넌트로 옮길 때도 라벨과 아이콘의 셀렉터를 분리할 것.
4. **미해결 항목** (화면구성도 7장 대응)
   - 곡선 차트 라이브러리: 목업은 손으로 그린 SVG. 실제로는 툴팁·크로스헤어·기간 토글이 필요하다.
     범위 밴드 + 기준선 2개 + 구간 음영을 지원하는 라이브러리를 고를 것
   - 캘린더 컴포넌트: 셀에 4가지 정보(순입출금·잔액·등급·플래그)를 넣어야 해 기성품이 잘 안 맞는다
   - Pretendard 배포 방식 (self-host vs dynamic subset)
   - 라우트 표기는 화면구성도의 안(案)을 그대로 썼다. 라우터 설계 시 확정
