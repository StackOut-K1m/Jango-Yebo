# 잔고예보 목업

기능명세서 SRS v1.2의 **P0 13개 · P1 18개 전 기능**과 화면구성도 **SC-01~SC-10**을 시연할 수 있는 고완성도 시안이다.

같은 화면의 **구조 전용 와이어프레임**은 [`../wireframe/`](../wireframe/)에 있다. 마크업은 같고 스타일시트만 다르다.

## 실행

프로젝트 루트에서 서버를 띄운다. 와이어프레임과 목업을 오가려면 루트 기준이어야 한다.

```bash
python -m http.server 4180
```

| 주소 | 내용 |
| --- | --- |
| `http://localhost:4180/mockup/` | 목업 (이 문서) |
| `http://localhost:4180/wireframe/` | 구조 전용 와이어프레임 |
| `http://localhost:4180/mockup/mobile.html` | **모바일 전 화면** (375px 아트보드 37개) |
| `http://localhost:4180/mockup/figma.html` | Figma 임포트용 (PC·태블릿·모바일 43개) |
| `http://localhost:4180/mockup/catalog/` | 화면 명세 카탈로그 (아트보드 11개) |

상단 **`화면 목록`** 버튼을 누르면 13개 화면과 각 화면이 덮는 기능 ID가 나온다. 시연은 여기서 시작하는 것이 빠르다.

### 예보(Forecast) 언어

이 제품은 이름부터 '예보'다. 일기예보의 정보 구조를 빌려 오되, 날씨 앱의 장난스러움은 가져오지 않는다.

| 일기예보 | 잔고예보 | 부품 |
| --- | --- | --- |
| 기상특보 배너 | 부족 경보 | `.alertband` |
| 현재 기온 | 지금 잔고 | `.wx-now .amount` |
| 체감온도 | 지금 써도 되는 돈 | `.wx-sub` |
| 시간별 예보 띠 | 날짜별 잔고 띠 | `.daystrip` |
| 주간 예보 목록 | 30일 예보 목록 | `.fc-list` |
| 최고/최저 막대 | 최소~최대 예상 범위 | `.range` |
| 맑음 / 구름 / 비 | 여유 / 빠듯 / 부족 | `.lv` |

**상자를 기본으로 쓰지 않는다.** 묶음은 `.panel`(테두리·배경 없이 제목과 여백으로만 구분)이 맡고,
`.card`는 **그 자체가 하나의 대상일 때만** 쓴다 — 누를 수 있는 것, 낱개로 존재하는 것(대출 한 건, 공고 한 건, 반복 후보 한 건).

지표 넷을 카드 넷으로 만들지 않는다. `.stats`가 세로 구분선만으로 나눈다.

> 상자를 걷어낸 자리는 **본문 흰 바탕 + 예보 판의 옅은 하늘 그라디언트**가 대신한다.
> 소그룹 구분은 `--surface-2` 회색 면이 맡는다.

### 지키기로 한 것

- **금액에는 색을 쓰지 않는다.** 방향은 부호(`+`/`−`)와 우측 정렬 `tabular-nums`로 말한다. 색은 차이·부족·실패에만 쓴다.
- **상태는 색과 함께 글자로도** 적는다. 이 규칙 덕분에 `../wireframe/`에서 색을 전부 지워도 화면이 읽힌다.
- **좁아질 때 정보를 숨기지 않는다.** 표는 열을 자르는 대신 카드로 바꾸고, 기준 시각과 재시도 버튼은 어느 폭에서도 남긴다.
- **예측을 확정으로 말하지 않는다.** 범위(82만~96만) · 신뢰도 · 기준 시각 · 근거를 늘 병기한다.
- **서비스가 원인을 확정하지 않는다.** 정산 차이의 원인은 후보 ①②③으로만 제시한다.
- **되돌릴 수 있는 일에는 확인 창 대신 5초짜리 되돌리기.** 확인 창은 지우기처럼 되돌릴 수 없는 일에만 쓴다.
- **Disabled는 회색으로만 두지 않는다.** 왜 못 누르는지와 어떻게 하면 눌리는지를 버튼 바로 아래에 적는다.

## Figma로 옮기기 — `figma.html`

**`index.html`을 그대로 가져오면 안 된다.** SPA라서 플러그인이 읽는 시점에 활성 화면 하나와 활성 탭 하나만 DOM에 있고, 겹쳐 뜨는 Drawer·Modal·Sheet는 아예 없다. 43개 화면 중 1개만 들어온다.

Figma용으로는 **`figma.html`** 을 쓴다. 모든 화면 × 모든 탭 × 겹쳐 뜨는 화면을 한 페이지에 동시에 펼친 정적 시트다.

| | `index.html` | `figma.html` |
| --- | --- | --- |
| 성격 | 눌러 보는 프로토타입 | 임포트용 아트보드 시트 |
| 한 번에 보이는 화면 | 1개 | **43개** |
| 탭 | 활성 탭만 | **탭마다 아트보드 하나** |
| Drawer · Modal · Sheet | 닫혀 있음 | **각각 아트보드** |
| CSS | 외부 파일 2개 | **전부 인라인** |
| JS | 있음 (표·달력을 채움) | **없음** (미리 렌더해 둠) |

| 대응 | 6 | SC-06 · SC-09 · SC-10(탭 4) |

| 겹쳐 뜨는 화면 | 4 | 거래 상세 Drawer · 일회성 거래 Modal · 더보기 시트 · 화면 목록 시트 |

### 가져오는 방법

두 가지 다 된다.

1. **URL로** — 서버를 띄우고 html.to.design 계열 플러그인에서 `http://localhost:4180/mockup/figma.html`
2. **붙여넣기로** — `figma.html` 내용을 그대로 복사해 플러그인의 HTML 입력란에 넣는다. CSS가 전부 인라인이라 서버 없이도 같은 결과가 나온다.

가져올 때 **뷰포트 폭은 1600px 이상**으로 잡는다. 1440px 아트보드가 잘리지 않아야 한다.

> 폰트만 CDN 링크로 남아 있다(Pretendard). 오프라인에서 가져와야 하면 그 `<link>` 한 줄을 지우고 시스템 폰트로 받거나, 폰트 파일을 저장소에 넣고 `@font-face`로 바꾼다.

### 다시 만들기

**`figma.html`을 손으로 고치지 않는다.** 목업 화면을 고친 뒤 스크립트를 다시 돌린다.

```bash
python mockup/build-figma.py         # → mockup/figma.html
python mockup/build-mobile.py        # → mockup/mobile.html
python wireframe/build-wireframe.py  # → wireframe/index.html
```

**목업 화면을 고치면 이 둘을 항상 같이 돌린다.** 손으로 관리하면 어긋난다.
검토보고서 **D-01**에서 겪은 문제와 같은 종류다.

### 모바일만 볼 때 — `mobile.html`

목업은 반응형이라 창을 좁히면 모바일이 된다. 다만 그렇게 보면 **한 번에 한 화면**만 볼 수 있고 화면마다 폭을 다시 맞춰야 한다.

`mobile.html`은 화면·탭 33개와 겹쳐 뜨는 화면 4개를 **전부 375px 프레임에 담아 한 장에** 늘어놓는다.
모바일 전용 마크업을 따로 쓰지 않았다 — **목업과 같은 HTML**이 좁은 폭에서 어떻게 접히는지를 그대로 보여 준다.

| 좁아지면 | 이렇게 된다 |
| --- | --- |
| 사이드바 13메뉴 | 하단 탭 4개 + 더보기 시트 |
| 거래 7열 표 | 카드 목록 (금액을 자르지 않는다) |
| 목록+상세 2단 | 1단 |
| 지표 4열 | 2열 |
| 서랍 400px | 전폭 |
| 모달 | 하단 시트 |
| 터치 영역 | 전부 44px 이상 |

Figma에 넣을 때도 이 파일을 쓰면 모바일만 따로 가져올 수 있다.
