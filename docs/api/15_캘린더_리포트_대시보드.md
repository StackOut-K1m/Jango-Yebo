### 15.2 AI 주간/월간 브리핑 (P1-17)

`GET /businesses/{businessId}/briefings?periodType=WEEKLY&page=0&size=10`

`GET /briefings/{briefingId}`

```json
{
  "success": true,
  "data": {
    "briefingId": 91,
    "businessId": 11,
    "periodType": "WEEKLY",
    "periodStart": "2026-08-24",
    "periodEnd": "2026-08-30",
    "headline": "정산 입금은 줄고 급여 출금을 앞두고 있어요",
    "content": "이번 주 요약: 화요일 정산금이 평소보다 12% 적게 들어왔고, 9월 14일 급여 출금 후 잔액이 빠듯합니다. 9월 15일 플랫폼 정산 입금 전까지 큰 지출은 피하는 것이 좋겠습니다.",
    "metrics": [
      {
        "label": "화요일 정산 입금",
        "value": 748000,
        "changeRate": -0.12,
        "sourceRef": { "type": "TRANSACTION", "transactionId": 88001 }
      },
      {
        "label": "향후 30일 최저잔액",
        "value": -420000,
        "sourceRef": { "type": "FORECAST", "date": "2026-09-14" }
      }
    ],
    "status": "COMPLETED",
    "generatedAt": "2026-08-31T00:05:00Z"
  }
}
```

- 브리핑은 주간(매주 월요일)·월간(매월 1일) 배치로 생성한다. 수치는 백엔드 계산 엔진 산출값만 사용하고 LLM은 문장 변환만 담당한다(20.2). `metrics`의 모든 수치는 근거 데이터(`sourceRef`)와 연결된다.
- 문장의 조언은 "권장" 수준으로 제한하고 확정 표현을 사용하지 않는다.
- 생성 실패 시 `status = FAILED`이며 지표 데이터(`metrics`)만이라도 반환한다.

```json
        "sourceRef": { "type": "ITEM", "itemId": 601 }
      }
    ],

  }

```

- 카테고리별 월간 집계, 전월·전년 동월 대비 증감, 수익 구조(카드/배달/현금 비중)를 제공한다.
- 아직 마감되지 않은 당월을 조회하면 현재까지 집계와 `isPartial: true`를 반환한다.
- 월간 리포트는 P1-17 월간 브리핑의 근거 데이터로 재사용된다.

**`income.byProduct` — 상품별 매출 기여도 (P1-22 연동)**

*"이번 달 매출이 왜 줄었나"* 에 답하는 블록이다. `income.byChannel`이 **어느 경로로** 들어왔는지를 말하고, `byProduct`가 **무엇이 팔려서** 달라졌는지를 말한다.

| 필드 | 설명 |
| --- | --- |
| `available` | 해당 월에 상품별 매출(14.4)이 등록됐는지. `false`면 `items`는 빈 배열이고 화면은 등록 유도 CTA를 띄운다 |
| `basisPeriod` | 구성비 근거 기간. 등록 기간이 달력 월과 다를 수 있으므로(월중 출력) 실제 기간을 밝힌다 |
| `shareBasis` | `BILLED`(합계 기준) · `GROSS`. 14.5와 동일 |
| `incomplete` | 근거 기간에 `checksumStatus = MISMATCHED`가 섞였는지. `true`면 "일부 행이 누락된 집계" 표시를 요구한다 |
| `contributionToChange` | **총매출 변동 중 이 상품이 차지한 금액.** 14.5에서 계산한 값을 그대로 쓴다 |

- `contributionToChange`의 분모는 `income.total`이다. 구성비(비율)에 계좌 입금 총액을 곱해 금액으로 환산하므로, **상품 기여도의 합과 `income.momChangeRate`의 분모가 같아진다.** 사용자 입력 절대액을 쓰던 이전 설계에서는 이 둘이 맞지 않았다.
- 환산값이므로 **추정치다.** 화면에서 상품별 금액은 "약" 표기 또는 비율 우선 표기로 제시한다. 정확한 금액의 단일 출처는 계좌 입금이다.
- 상품별 매출은 **금액이 아니라 구성비로만** 이 리포트에 들어온다. 세무 집계·부가세에는 들어가지 않는다(ERD 1.9 「소비처와 비소비처」, API 14.3).
- `highlights`에 `SALES_DECREASE` 타입을 생성할 때 `sourceRef`로 `{ "type": "PRODUCT", "productKey": "콜드브루" }`를 연결한다. P1-17 브리핑은 이 근거만 문장화하고 수치를 만들지 않는다.
- 원가를 모르므로 **수익성·단종 권고를 하지 않는다**(14.5 표현 제약).
