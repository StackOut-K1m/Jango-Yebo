## 12. 안전선·준비금·부가세

### 12.1 운영자금 안전선 (P1-08)

`GET /businesses/{businessId}/safety-line`

```json
{
  "success": true,
  "data": {
    "amount": 2000000,
    "method": "FIXED_COST_BASED",
    "autoUpdate": false,
    "updatedAt": "2026-08-20T09:00:00Z",
    "current": {
      "currentBalance": 5000000,
      "riskLevel": "SAFE",
      "next30dLowestBalance": 1200000,
      "next30dLowestDate": "2026-09-14",
      "shortfallAgainstLine": 800000,
      "firstBelowLineDate": "2026-09-12",
      "causes": [
        { "date": "2026-09-14", "title": "급여 3,000,000원 출금", "plannedTransactionId": 502 }
      ]
    }
  }
}
```

`PUT /businesses/{businessId}/safety-line`

```json
{
  "amount": 2000000,
  "method": "MANUAL",
  "autoUpdate": false
}
```

- `method`: `MANUAL`(직접 입력), `FIXED_COST_BASED`(최근 한 달 고정비 기준), `ESSENTIAL_EXPENSE_BASED`(급여·임대료 등 필수지출 합계 기준)
- `autoUpdate = true`이면 매월 고정비 집계로 금액을 자동 갱신한다.
- 사업장별로 개별 설정한다 (P1-08). 설정 전에는 `amount: null`이며 위험 등급은 0원 기준만 판정한다.

`GET /businesses/{businessId}/safety-line/recommendations`

```json
{
  "success": true,
  "data": {
    "fixedCostBased": {
      "amount": 2200000,
      "basis": "최근 30일 고정비(임차료·급여·보험료·구독료) 합계"
    },
    "essentialExpenseBased": {
      "amount": 1800000,
      "basis": "월 급여 + 임차료 합계"
    },
    "referencePeriod": "2026-08-01~2026-08-30"
  }
}
```

### 12.2 가상 준비금 (P1-09)

준비금은 서비스 내부의 가상 적립이며 실제 계좌 분리·이체는 발생하지 않는다.

`GET /businesses/{businessId}/reserves?status=ACTIVE`

```json
{
  "success": true,
  "data": {
    "items": [
      {
        "reserveId": 41,
        "purpose": "9월 급여",
        "category": "PAYROLL",
        "targetAmount": 3000000,
        "targetDate": "2026-09-14",
        "linkedPlannedTransactionId": 502,
        "securedAmount": 1200000,
        "progressRate": 0.4,
        "remainingAmount": 1800000,
        "remainingBusinessDays": 6,
        "dailyAmount": 300000,
        "priority": 1,
        "status": "ACTIVE",
        "achievable": true
      }
    ]
  }
}
```

`POST /businesses/{businessId}/reserves`

```json
{
  "purpose": "9월 급여",
  "category": "PAYROLL",
  "targetAmount": 3000000,
  "targetDate": "2026-09-14",
  "linkedPlannedTransactionId": 502,
  "priority": 1
}
```

- `linkedPlannedTransactionId`를 지정하면 대상 지출의 날짜·금액 변경이 준비금 목표에 자동 반영된다.
- 부가세 준비금(P1-11)은 `category = VAT`로 서버가 자동 생성·제안한다.
- `PATCH /reserves/{reserveId}` — 수정 가능 필드: `purpose`, `targetAmount`, `targetDate`, `priority`, `status`(`ACTIVE`/`PAUSED`/`COMPLETED`)
- `POST /reserves/{reserveId}/deposits` — `{ "amount": 300000, "date": "2026-08-31" }`로 오늘 확보한 금액을 기록한다. `securedAmount`에 누적된다.

### 12.3 오늘 모아둘 돈 계산

`GET /businesses/{businessId}/reserves/daily-plan?basis=SAFE`

```json
{
  "success": true,
  "data": {
    "baseTime": "2026-08-31T02:00:00Z",
    "date": "2026-08-31",
    "basis": "SAFE",
    "totalDailyAmount": 300000,
    "achievable": true,
    "items": [
      {
        "reserveId": 41,
        "purpose": "9월 급여",
        "dailyAmount": 250000,
        "priority": 1,
        "note": "지급일 임박"
      },
      {
        "reserveId": 42,
        "purpose": "부가세 준비금",
        "dailyAmount": 50000,
        "priority": 2,
        "note": null
      }
    ],
    "carryOver": {
      "missedYesterdayAmount": 50000,
      "redistributed": true
    },
    "unachievableFallback": null,
    "confidence": "HIGH",
    "warnings": []
  }
}
```

- 계산식: `남은 준비금 = 목표금액 − 확보 금액`, `하루 준비금 = 남은 준비금 ÷ 남은 영업일`. 영업일은 공휴일 캘린더(P1-04) 기준이다.
- `basis`: `SAFE`(확정 입금만 반영, 기본값), `EXPECTED`(확인된 예정 정산금 포함)
- 복수 준비금 배분 우선순위: 지급일 임박 → 필수지출 → 연체 위험 → 조정 불가 → 일반. `priority`로 사용자가 변경할 수 있다.
- 어제 목표 미달분은 오늘 이후 목표에 재배분한다 (`carryOver`).
- 달성 불가로 판정되면 `achievable = false`와 함께 `unachievableFallback`에 대응 기능 연결 정보(시나리오·지원 제도·대출 추천)를 담는다.

### 12.4 부가세 예수금 현황 (P1-11)

`GET /businesses/{businessId}/vat/status`

```json
{
  "success": true,
  "data": {
    "baseTime": "2026-08-31T02:00:00Z",
    "taxationType": "GENERAL",
    "currentPeriod": {
      "periodStart": "2026-07-01",
      "periodEnd": "2026-12-31",
      "filingDueDate": "2027-01-25",
      "nextPrepaymentDate": "2026-10-25"
    },
    "estimatedVatHeld": 3200000,
    "estimatedInputVat": 1400000,
    "estimatedPayable": { "min": 1500000, "max": 2100000 },
    "availableBalance": {
      "accountBalance": 5000000,
      "vatExcluded": 1800000,
      "description": "부가세 예수금을 제외한 사용 가능 잔액"
    },
    "reserve": {
      "reserveId": 42,
      "weeklyRecommendedAmount": 250000,
      "securedAmount": 800000
    },
    "appliedToForecast": true,
    "taxYear": 2026,
    "disclaimer": "매입세액·공제에 따라 실제 납부액은 달라질 수 있습니다. 신고 전 세무전문가 확인이 필요합니다.",
    "confidence": "MEDIUM",
    "basis": {
      "vatFormula": "과세 매출 입금의 10/110 합산",
      "inputVatSource": "확정 증빙의 부가세 필드 합산"
    },
    "warnings": []
  }
}
```

- `estimatedVatHeld`는 과세 매출 입금(공급대가)의 10/110을 자동 분리한 예수금 추정치다.
- **예수금 계산 방식은 이 한 가지만 유지한다.** 상품별 매출(P1-22)의 `vatAmount`는 POS 인쇄물에서 함께 읽히지만 **여기에 쓰지 않는다.** 두 번째 부가세 숫자를 만들면 어느 값이 기준인지 알 수 없고, 판매 층은 정산 전 총매출이라 입금 기준 예수금과 분모가 다르다. 판매 층은 구성비만 내보낸다(공통규약 1.5, ERD 1.9 「소비처와 비소비처」).
- 과세 유형(`GENERAL`/`SIMPLIFIED`)에 따라 신고·납부 일정을 다르게 계산한다: 일반과세자는 1·7월 확정신고와 4·10월 예정고지, 간이과세자는 1월 연 1회.
- 다음 납부 예정액은 `source = TAX` 예정 거래로 잔액 예측 곡선에 자동 반영된다 (P0-07 연동).
- 주 단위 적립 추천은 준비금 엔진(12.3)을 재사용한다.
- 납부액은 항상 범위로 표시하고 확정값을 반환하지 않는다.
