## 19. 다사업장 통합과 자금 융통

### 19.1 통합 대시보드 (P1-12 기본형)

`GET /users/me/dashboard`

```json
{
  "success": true,
  "data": {
    "baseTime": "2026-08-31T02:00:00Z",
    "totalBalance": 12400000,
    "businesses": [
      {
        "businessId": 11,
        "name": "카페 한잔",
        "currentBalance": 5000000,
        "riskLevel": "CAUTION",
        "nearestGapDate": "2026-09-14",
        "next30dLowestBalance": -420000
      },
      {
        "businessId": 12,
        "name": "카페 두잔",
        "currentBalance": 7400000,
        "riskLevel": "SAFE",
        "nearestGapDate": null,
        "next30dLowestBalance": 3100000
      }
    ],
    "combined": {
      "next30dLowestBalance": 2680000,
      "next30dLowestDate": "2026-09-14"
    },
    "activeAlertCount": 2
  }
}
```

- 전체 합산 흐름과 매장별 카드를 함께 반환한다. 매장별 잔액 예측은 사업장 단위로 독립 수행한 결과를 집계한다.

### 19.2 매장 간 자금 융통 시뮬레이션 (P1-12)

`POST /users/me/transfer-simulations`

```json
{
  "date": "2026-09-14",
  "businessIds": [11, 12]
}
```

```json
{
  "success": true,
  "data": {
    "baseTime": "2026-08-31T02:00:00Z",
    "date": "2026-09-14",
    "businesses": [
      {
        "businessId": 11,
        "name": "카페 한잔",
        "expectedBalance": -420000,
        "safetyLine": 2000000,
        "availableSurplus": 0,
        "shortfall": 2420000
      },
      {
        "businessId": 12,
        "name": "카페 두잔",
        "expectedBalance": 7100000,
        "safetyLine": 3000000,
        "availableSurplus": 4100000,
        "shortfall": 0
      }
    ],
    "plans": [
      {
        "fromBusinessId": 12,
        "fromAccountId": 25,
        "toBusinessId": 11,
        "toAccountId": 21,
        "amount": 2420000
      }
    ],
    "resolvedAmount": 2420000,
    "unresolvedAmount": 0,
    "unresolvedSuggestions": [],
    "afterSimulation": [
      { "businessId": 11, "expectedBalance": 2000000, "riskLevel": "SAFE" },
      { "businessId": 12, "expectedBalance": 4680000, "riskLevel": "SAFE" }
    ],
    "disclaimer": "시뮬레이션 결과이며 실제 이체는 수행하지 않습니다."
  }
}
```

- `가용잉여금 = 예상잔액 − 안전잔액`으로 매장별 잉여를 계산하고, 잉여 매장 → 부족 매장 이체 계획을 최소비용 최대유량(MCMF)으로 산출해 이체 건수를 최소화한다.
- `businessIds`를 생략하면 사용자의 전체 사업장을 대상으로 한다.
- 이체만으로 메울 수 없는 `unresolvedAmount`가 남으면 `unresolvedSuggestions`에 지원 제도(P1-15)·대출(P1-13/14) 연계 정보를 담는다.
- 사업장 간 자금 이동은 가상 계산으로만 다루며 실제 이체·예약이체 API는 범위에서 제외한다. 결과는 저장하지 않는 즉시 계산 응답이다(`200 OK`).
