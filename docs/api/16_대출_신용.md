## 16. 대출과 신용

### 16.1 대출 현황 (P1-13)

`GET /businesses/{businessId}/loans`


`POST /businesses/{businessId}/loans` — 수동 등록. 필드: `loanType`(기본 `TERM_LOAN`), `lenderName`, `productName`, `principal`, `balance`, `interestRate`, `repaymentType`(`EQUAL_PRINCIPAL_INTEREST`/`EQUAL_PRINCIPAL`/`BULLET`), `monthlyPaymentDay`, `maturityDate`, `withdrawalAccountId`.

`POST /businesses/{businessId}/loans/sync` — SSAFY 금융망의 대출 가입 목록·상환 내역·마이너스통장 목록을 동기화한다. `202` + `LOAN_SYNC` Job.

- `loanType`: `TERM_LOAN`(일반 대출), `MINUS_ACCOUNT`(마이너스통장). 마이너스통장은 한도(`creditLimit`)·사용액(`usedAmount`)·출금 가능액(`availableAmount`)·누적 이자(`accruedInterest`)·이자 납입일(`interestPaymentDay`)을 관리한다.
- `status`: `NORMAL`(정상), `REPAYING`(상환중), `OVERDUE`(연체), `CLOSED`(해지·상환 완료) — 금융망 대출 계좌 상태(개설/상환중/연체)를 매핑한다.
- `repaymentCycle`: `MONTHLY`(수동 등록 기본) / `DAILY`(금융망 연동 대출 — 개설 다음날부터 매일 오전 출금 계좌에서 자동 상환). `source = LOAN` 예정 거래 생성 규칙이 유형별로 다르다: `MONTHLY`는 월 상환일, `DAILY`는 일 단위 상환액, 마이너스통장은 이자 납입일 기준으로 생성한다. `DAILY` 의 총상환액은 금융망 실측 식 **`P·(1 + r·d²/365)`** 다(2026-09-16 세 점 확정 — 기술스택 4.13) — 플로우 문서의 단리 일할이 아니다. 16.3 의 `totalRepayment`·`dailyPayment` 와 11.1 `LOAN_EXECUTION` 이 이 식을 쓴다.
- `withdrawalAccountId`는 상환금이 출금되는 연결 계좌이며, 해당 계좌의 잔액 예측에 상환 지출이 반영된다.
- 등록·동기화된 대출의 상환 스케줄은 `source = LOAN` 예정 거래로 예측 엔진에 자동 반영된다 (P1-13 완료 기준).
- 캘린더에서 상환일과 공백일이 겹치는 구간은 잔액 곡선의 `riskLevel`로 드러나며, 상세 조회의 `basis`로 원인을 확인한다.


- 등급 체계는 금융망 신용등급 기준 조회(A~E 5등급)와 등급별 자산 구간을 그대로 사용하며, 화면 표시용으로 `gradeCriteria`를 함께 반환한다.
- `assets`는 금융망 내 신용등급 조회가 반환하는 수시입출금·예·적금 자산을 그대로 반영한 값이다.


- 상품 데이터는 금융망 대출 상품 조회를 동기화한 것이다. 금리는 상품별 단일값(`interestRate`), 대출 기간은 일 단위(`loanPeriodDays`)이며, `isEligibleNow`는 현재 등급과 상품의 최소 가입 등급(`minGrade`) 비교로 계산한다.
- 대출 실행 시 잔액 곡선 변화 미리 보기는 시나리오 API의 `LOAN_EXECUTION` 파라미터(11.1)를 사용한다.
- 이 API는 조회·추천·시뮬레이션까지만 제공하며 실행 API는 정의하지 않는다.
