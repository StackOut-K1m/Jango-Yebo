## 6. 인증과 사용자

### 6.1 회원가입

`POST /auth/signup`

```json
{
  "email": "owner@example.com",
  "password": "StrongPass!23",
  "name": "김사장",
  "phone": "010-1234-5678"
}
```

```json
{
  "success": true,
  "data": {
    "userId": 101,
    "email": "owner@example.com",
    "name": "김사장"
  }
}
```

- 비밀번호는 8~64자이며 영문, 숫자, 특수문자를 포함한다.
- 이메일 중복은 `409 AUTH_EMAIL_DUPLICATED`를 반환한다.
- 가입 시 서버가 SSAFY 금융망 사용자 계정을 생성(이미 있으면 조회)하고 발급된 `userKey`를 암호화 저장한다. `userKey`는 이후 모든 금융망 호출(계좌·거래·대출·신용등급)에 사용하며 API 응답에는 노출하지 않는다. 금융망 계정 생성에 실패해도 가입은 완료하고 계좌 연결 시점에 재시도한다.

### 6.2 로그인·토큰 갱신·로그아웃

`POST /auth/login`

```json
{
  "email": "owner@example.com",
  "password": "StrongPass!23"
}
```

```json
{
  "success": true,
  "data": {
    "accessToken": "eyJhbGciOi...",
    "expiresIn": 1800,
    "user": {
      "userId": 101,
      "name": "김사장",
      "defaultBusinessId": 11
    }
  }
}
```

| Method | Endpoint | 설명 |
| --- | --- | --- |
| POST | `/auth/refresh` | Refresh Token으로 새 Access Token 발급 (쿠키 또는 본문) |
| POST | `/auth/logout` | Refresh Token 폐기, `204 No Content` |

#### 앱(React Native) — Refresh Token을 본문으로

앱에는 쿠키 저장소가 없어 `HttpOnly` 쿠키를 받지 못한다. 채널만 다르고 나머지(회전·수명·오류)는 같다. 배경과 보안 조건은 [공통규약 2.1](./00_공통규약.md#21-url과-인증)을 본다.

`POST /auth/login` — 헤더 `X-Client-Type: app`을 붙이면 본문에 두 필드가 더 붙고 `Set-Cookie`가 내려오지 않는다.

```json
{
  "success": true,
  "data": {
    "accessToken": "eyJhbGciOi...",
    "expiresIn": 1800,
    "refreshToken": "eyJhbGciOi...",
    "refreshExpiresIn": 1209600,
    "user": { "userId": 101, "name": "김사장", "defaultBusinessId": 11 }
  }
}
```

`POST /auth/refresh` · `POST /auth/logout` — 폐기·갱신할 토큰을 본문으로 보낸다.

```json
{ "refreshToken": "eyJhbGciOi..." }
```

- **채널은 토큰이 온 곳이 정한다.** 본문으로 보내면 새 토큰도 본문으로, 쿠키로 보내면 쿠키로 온다. `X-Client-Type`을 붙여도 쿠키로 온 요청에는 본문으로 토큰을 주지 않는다.
- 회전은 웹과 같다 — 쓴 토큰은 즉시 폐기되고, 재사용하면 `401 AUTH_TOKEN_INVALID`다. 이때 앱은 로그인 화면으로 보낸다.
- 로그아웃은 쿠키·본문이 모두 없어도 조용히 `204`다.
- 웹은 아무것도 달라지지 않는다. 헤더 없는 로그인과 쿠키 갱신의 응답 본문에는 `refreshToken`이 **없다**.

### 6.3 내 프로필

`GET /users/me`

```json
{
  "success": true,
  "data": {
    "userId": 101,
    "email": "owner@example.com",
    "name": "김사장",
    "phone": "010-1234-5678",
    "defaultBusinessId": 11,
    "businessCount": 2,
    "createdAt": "2026-08-01T09:00:00Z"
  }
}
```

`PATCH /users/me` — 수정 가능 필드: `name`, `phone`, `defaultBusinessId`.
