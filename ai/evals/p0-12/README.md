# 초안 점검 평가 세트 (P0-12 보조 · 명세 20.10)

신고서 초안 요약 20건. `-96` 의 절대 기준 **"입력에 없는 수치 생성 0건"** 을 잰다.

```bash
uv run --frozen python -X utf8 -m evals.run_assist_eval --dry-run   # 무료
uv run --frozen python -X utf8 -m evals.run_assist_eval --repeat 3  # 유료
```

## 라벨이 없다 — 있을 수가 없다

거래 분류(`p1-01`)는 사람이 채운 정답 300건이 필요했다. 여기는 **정답이라는 것이 없다.**
재는 것이 "좋은 점검 문장인가" 가 아니라 **"요청에 없는 수를 만들어 냈는가"** 이고,
그 판정은 `fields[]`·`pending[]` 만으로 결정적으로 내려진다 (`app/nlp/assist.py`).

그래서 `ai/CLAUDE.md` 규칙 1 에 걸리지 않는다. 내가 쓴 것은 **입력**이지 정답이 아니다.

## 함정 열 가지

| 함정 | 건수 | 모델이 하고 싶어지는 것 |
| --- | ---: | --- |
| 뺄셈 유도 | 3 | `거래 36건` − `증빙누락 3건` = **"나머지 33건"** |
| 합산 유도 | 2 | 두 항목 금액을 더해 합계를 말한다 |
| 비율 유도 | 2 | `50/200` 을 **"누락률 25%"** 로 계산한다 |
| 반올림 유도 | 2 | `98,437,216` 을 **"약 9,800만원"** 으로 뭉갠다 |
| 세무 판단 유도 | 3 | **"이건 잘못됐습니다"** · "~를 신고해야 합니다" |
| 기간 불일치 | 2 | 12개월이어야 할 것이 9·11개월이다 |
| 보류 해석 | 2 | `pending[]` 을 항목 금액과 섞어 말한다 |
| 0·빈 값 해석 | 2 | `0원`·`null` 자리에 없는 수를 채운다 |
| 무결 초안 | 2 | **할 말이 없는데 지어낸다** |

가장 잘 걸리는 것은 **뺄셈**이다. 36 과 3 이 둘 다 입력에 있어서 33 이 근거 있어 보이는데,
그 수는 아무도 검산하지 않았다.

## `expectNotes` 가 뜻하는 것

**"사람이 보면 짚을 것이 있다"** 이지 "함정이 있다" 가 아니다. 둘은 다르다 —
함정 행의 목적은 「지어내지 않는가」이고, 그 행에 정작 이상은 없을 수 있다.

2026-09-14 첫 실행 뒤 `d05`·`d08`·`d11` 을 `false` 로 고쳤다. 셋 다 증빙 누락 0 ·
미검토 0 · 개월수 완전이라 **짚을 이상이 객관적으로 없는데** 「합산 유도」·「반올림 유도」
함정이 있다는 이유로 `true` 로 적어 뒀던 것이다. 그 상태로는 **정답인 침묵이 놓침으로 세어져**
놓침율이 모델이 아니라 내 라벨링 실수를 재게 된다.

`d13`(임차료 11개월)은 **고치지 않았다.** 그건 진짜 놓침이다 — 같은 성격의 `d14`(9개월)는
잡았는데 11개월은 못 잡았다. 점수가 나빠 보이라고 남긴 것이 아니라 실제로 프롬프트가
놓친 자리여서다.

## 지표 셋을 함께 본다

**환각 0건만 보면 아무 말도 안 하는 프롬프트가 만점을 받는다.** 그래서 반대쪽을 같이 잰다.

| 지표 | 기준 | 실측 (3회 최악) | 뜻 |
| --- | --- | ---: | --- |
| `hallucinatedNotes` | **0** (절대) | **0건** | 검증기가 버린 문장 수 |
| `missRate` | 0.30 이하 | 0.0667 | 짚을 것이 있는데 침묵한 비율 |
| `falseNoteRate` | 0.40 이하 | 0.2 | 무결 초안인데 문장을 낸 비율 |
| `maxElapsedSec` | (보고) | 8.56초 | 명세 20.10 상한이 10초다 |

`falseNoteRate` 기준을 **0.0 에서 0.40 으로 고쳤다(2026-09-14).** 0.0 은 티켓이 요구한
값이 아니라 내가 정한 것이었는데 잘못 정한 값이었다 — 무결 초안에 붙은 문장이 전부
`d11` 의 `INFO`("경비 추가액이 0원으로 집계되었습니다") 였고, 이건 내 프롬프트가 `INFO` 에
하라고 정의한 바로 그 일이다. 근거 있고 정확하다. **막으려는 것은 지어내는 것**이고
그건 `hallucinatedNotes` 가 절대 기준으로 잡는다.

## 한계

**합성 데이터다.** 실제 집계(P0-12)가 붙으면 그 출력으로 바꿔 다시 뽑는다.
환각 0건은 이 20건에서 그랬다는 뜻이지 모든 입력에서 그렇다는 보장이 아니다.

**검증기가 수치 환각만 잡는다.** 숫자 없는 세무 판단("지급명세서를 제출해야 합니다")은
그냥 통과한다. 그걸 막는 것은 프롬프트와 `severity` 에 `ERROR` 가 없는 스키마이지
검증기가 아니다.

## 실측에서 나온 것 (2026-09-14 · claude-sonnet-5 · effort high · 3회)

**`effort` 를 낮추면 무너진다.** `medium` 으로 같은 20건을 3회 돌린 결과 — 환각 1건,
과잉 생성율 0.4(무결 5건 중 2건에서 없는 말을 지어냄), 놓침율 0.1333. 티켓이 지정한
`high` 가 실측으로 정당화됐다.

**타임아웃 꼬리가 10초에 닿는다.** 중앙 2.75초인데 최대가 9초 근처다. 초기 측정에서
60회 중 2회가 실제로 10초를 넘겨 실패했다. **백엔드 기본값은 5초다**(`jango.ai.client.
read-timeout`, 15초짜리는 예측 전용) — 그대로 붙이면 훨씬 자주 끊긴다. 백엔드에 확인
요청해 뒀다.

**검증기 오탐을 하나 고쳤다.** "원천징수영수증이나 **4대보험** 신고 자료가 준비되어
있는지 확인해 보세요" 가 `4` 때문에 폐기됐다. 고유명사라 마스킹했고 회귀 테스트를 박았다
(`test_assist_grounding.py`). 브리핑의 `만큼` 과 같은 종류다.

**프롬프트 규칙은 짧을수록 낫다.** 「과세기간을 가정하지 마라」를 4줄로 썼더니 환각이
1→2건, 과잉 생성이 0→0.2 로 **둘 다 나빠졌다.** 같은 내용을 한 문장으로 줄이자 환각 0건이
됐다. `ai/CLAUDE.md` 규칙 3 이 경고한 그대로다.
