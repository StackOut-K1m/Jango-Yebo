# 시드 콘솔

시연 데이터를 화면에서 맞추는 개발 도구. `scripts/seed.mjs` 를 인자 바꿔 가며 매번 다시
돌리던 일을 대신한다.

**개발 전용이다.** 배포 경로에 넣지 않고, 프론트엔드(`frontend/`)와도 분리해 둔다 —
빌드에 섞이면 팀 apiKey 를 다루는 코드가 배포 산출물에 들어간다.

## 실행

```bash
npm run seed
```

`http://127.0.0.1:5181` 이 열린다. 포트를 바꾸려면 `PORT=6001 npm run seed`.

의존성이 없다. `node:http` 와 전역 `fetch` 만 쓰므로 설치 과정이 없다(Node 18+).

## 무엇을 준비해야 하나

| 값                     | 출처                | 없으면                                                      |
| ---------------------- | ------------------- | ----------------------------------------------------------- |
| `FINOPENAPI_API_KEY`   | `backend/.env`      | 미리보기·CSV 는 되고 **실행만** 막힌다                      |
| 백엔드                 | `http://localhost:8080` | 실행 단계가 "닿지 못했다"에서 멈춘다. 주소는 화면에서 바꾼다 |

`SEED_API_BASE` 로 기본 백엔드 주소를, `JANGO_REPO` 로 저장소 경로를 바꿀 수 있다.
저장소 밖에서 띄울 때 쓴다.

## 무엇이 어디에 있나

곡선을 만드는 것도 실제로 밀어 넣는 것도 **CLI 와 같은 코드**다. 화면과 명령어가 서로 다른
시드를 만들면, 그게 발표 전날 밤에 드러난다.

| 파일                       | 하는 일                                                       |
| -------------------------- | ------------------------------------------------------------- |
| `scripts/seed/plan.mjs`    | 거래를 만든다. 순수 함수만 — 네트워크도 파일도 안 건드린다     |
| `scripts/seed/pipeline.mjs`| 백엔드·금융망에 밀어 넣는다                                    |
| `scripts/seed.mjs`         | 위 둘을 CLI 로 엮는다                                          |
| `tools/seed-console/`      | 위 둘을 화면으로 엮는다                                        |

조정할 수 있는 값의 **기본치는 `plan.mjs` 의 `DEFAULT_TUNING`** 이 정하고,
**어떻게 보여주고 어디까지 허용할지는 `public/schema.mjs`** 가 정한다. 서버와 브라우저가
schema 를 같이 읽으므로 폼과 검증이 함께 따라온다(금융망 콘솔의 `catalog.mjs` 와 같은 규율).

## 화면

왼쪽 위에 **지금 이 값으로 공백이 남아 있나**가 고정돼 있다. 스크립트로 할 때 번거로웠던 게
정확히 이걸 매번 다시 확인하는 일이었다. 값을 고치면 곡선을 다시 구해 판정이 따라 바뀐다.

| 화면                | 무엇                                                                             |
| ------------------- | -------------------------------------------------------------------------------- |
| 잔액 곡선           | 날짜별 예상 잔액 · 월별 저점 · 예보 창 일별 종가                                 |
| 거래 · 합계         | 만들어질 거래 표본과 분류별 합계 · **상품별 매출 인쇄물 미리보기**               |
| 기간 · 앵커         | 기준일 · 과거 일수 · 공백을 어디에 얼마나 깊게 · 성장률 · 메우기 · 휴업일        |
| 수입 · 지출 · 메뉴  | 적요 · 금액 · 날짜 · 휴일 보정 · 분류. **고정비는 추가·삭제된다**                |
|                     | **상품 구성**이 메뉴별 비중을 정하고 월 인쇄물 한 장이 된다 — 아래 절 참고        |
|                     | 맨 아래 **주기 없는 거래**가 잔여를 만든다 — 아래 절 참고                        |
| 계정 · 사업장 · 계좌| 이메일 · 비밀번호 · 사업장 정보 · 계좌 구성 · 백엔드 주소                        |
| 시드 세우기         | 단계를 골라 실행. 진행이 한 줄씩 흐른다                                          |
|                     | 맨 아래 **「싹 지우고 처음부터 다시 세운다」**가 원버튼 재주입이다 — 아래 절 참고 |
| CSV · 설정 파일     | 거래 CSV · 분류 정답표 · CLI 로 넘길 설정 파일                                   |
| 직접 넣기           | 이미 있는 계정의 연결 계좌에 CSV 파일 올리기                                     |

### 실행 단계

전부 **쓰기**다. 금융망과 우리 DB 를 실제로 바꾸므로 실행 전에 무엇이 어떻게 되는지
한 번 보여 준다. 고른 단계에 **선행 단계가 자동으로 얹힌다** — "업로드만 할게"를 눌렀는데
계좌가 없어서 실패하는 것보다 낫다.

```
계정 확보 → [선택] 기존 시드 지우기 → 사업장 확보 → 금융망 계좌 확보 → 계좌 연동·1원 인증
         → 과거 거래 업로드 → 금융망 잔액 맞추기 → 동기화 접수
         → 잔액 맞추기 흔적 제외 → 상품별 매출 등록
         → [선택] 반복 후보 승인 → [선택] 예정 거래 자동 반영 켜기
```

선택 셋은 **기본으로 꺼져 있다.**

**기존 시드 지우기** — 되돌릴 수 없는 유일한 단계다. 자세한 것은 아래 「잘못 넣은 시드를
고치는 법」에 있다. **세우기 앞에** 오므로, 켜고 실행하면 「지우고 → 다시 세우기」가 한 번에
끝난다.

**잔액 맞추기 흔적 제외** — 「전기이월」·「개발용 초기 잔액」을 예측 입력에서 뺀다. 골라 두지
않아도 「금융망 잔액 맞추기」가 끌고 온다. 빼지 않으면 잔액을 맞추려고 넣은 입금이 평소
매출로 읽힌다 — 지우지 않고 표시만 한다.

**상품별 매출 등록** — 월 단위 상품 구성비를 사업장에 넣는다(P1-22, API 14.4). 계좌와 무관해
「계정 확보 → 사업장 확보」만 얹힌다. 왜 시드가 넣는지는 아래 절에 있다.

**반복 후보 승인** — 탐지한 후보를 전부 확정해 예정 거래를 만든다. 예정 거래는 **승인해야
생기므로** 자동 반영도 이 단계가 있어야 할 일이 생긴다. 그런데 발표에서는 사장님이 화면에서
「맞아요」를 누르는 것이 시연 흐름이라, 리허설·로컬에서만 켜는 것을 권한다.

**예정 거래 자동 반영 켜기** — 그 계좌에 스위치를 켠다. 켜면 서버가 **예정일마다 그 계좌에서
실제로 출금·입금한다**(API 9.6). 시연 데이터가 날짜를 넘겨도 스스로 움직이게 하려는 장치다.

> ⚠ **로컬과 서버 중 한쪽에서만 켜십시오.** `userKey` 가 이메일에서 나오므로 같은 계정으로
> 양쪽을 시드하면 **두 서버가 같은 금융망 계좌를 봅니다.** 중복 출금은 서버가 보내기 전에
> 금융망 거래내역을 확인해 막지만, 굳이 둘 다 켤 이유는 없습니다.

몇 번을 돌려도 같은 상태가 된다. 거래는 고정 시드 PRNG 라 같고, 업로드는 중복 판정이
흡수하며, 사업장·계좌는 이미 있으면 다시 만들지 않는다. 이미 인증된 계좌에 1원을 또 쏘지도 않는다.

**그 성질이 잘못 넣었을 때는 반대로 작용한다.** 재실행이 덮어쓰기가 아니라 건너뛰기라,
틀린 거래 위에 맞는 거래가 덧쌓인다. 그때가 「기존 시드 지우기」를 쓰는 자리다 —
아래 「잘못 넣은 시드를 고치는 법」.

### 설정 파일

화면에서 맞춘 값을 받아 그대로 CLI 에 넘긴다. 발표 당일 아침에 브라우저를 열 것 없이
이 파일 하나면 된다.

```bash
node scripts/seed.mjs --tuning seed-out/시드설정_2026-09-28.json
```

`{ asOf, owner, accounts, tuning }` 네 칸이고 전부 선택이다. 빠진 칸은 기본값이 채운다.

> ⚠ **비밀번호가 들어 있는 파일이다.** 저장소에 커밋하지 않는다(`seed-out/` 은 gitignore).

## 잘못 넣은 시드를 고치는 법

**다시 돌린다고 안 고쳐진다.** 이 도구의 재실행은 *덮어쓰기가 아니라 건너뛰기*다 — 사업장과
계좌는 이미 있으면 안 만들고 거래는 중복 판정이 흡수한다. 금액을 잘못 맞춘 채로 한 번
올리면, 고친 값으로 다시 돌려도 **틀린 거래 위에 맞는 거래가 덧쌓인다.**

그래서 지우는 문을 따로 뒀다. 실행 탭 맨 아래 빨간 버튼 하나다.

```
싹 지우고 처음부터 다시 세운다
```

누르면 단계를 대신 골라 주고(기본 단계 + 지우기) 한 번 더 묻는다. 하는 일은 순서대로

1. **연동 해제** — `CONNECTED` 계좌만. 삭제가 연결된 계좌를 막기 때문이고, 해제가 자동 반영
   스위치를 함께 꺼서 워커가 금융망에 출금을 보내는 창이 닫힌다
2. **계좌 삭제** (API 7.2 `POST /accounts/{id}/purge`) — 계좌와 **그 계좌의 거래**를 지운다.
   예정 거래·반복 패턴·정산 배분도 함께 걷힌다. 증빙과 대출은 **연결만 끊긴다**
3. **금융망 잔액 비우기** (DD_08) — 해지에는 잔액이 0 이어야 한다. 아니면 금액반환계좌를
   물어 오는데 돌려줄 곳이 없다
4. **금융망 계좌 해지** (DD_14)
5. 그다음 기본 단계를 그대로 돌려 **처음부터 다시 세운다**

CLI 는 `--reset` 이고, 지우기만 할 거면 `--reset-only` 다.

```bash
node scripts/seed.mjs --reset --tuning seed-out/시드설정.json
```

### 왜 금융망에서까지 해지하나

우리 DB 만 지우면 **금융망 계좌는 그대로 남는다.** 다음 시드의 「금융망 계좌 확보」가 번호
순으로 **그 계좌를 다시 집고**, 지난 시드가 남긴 오늘 거래를 동기화가 되살린다. 계좌 자체를
없애야 다음 시드가 새 번호로 시작한다.

**싸피은행(999) 계좌만 건드린다.** 개발·시연 계좌는 거기 만든다는 것이 팀 관례라
(`scripts/fin-account.mjs`) 그 userKey 의 999 계좌는 전부 도구가 만든 것이다. **연동된 적
없는 계좌도 해지한다** — 시드가 중간에 죽으면 만들어만 놓고 연결 못 한 계좌가 남는데,
그것이야말로 다음 시드가 조용히 집어 쓰는 쓰레기다. 로그가 「연동된 적 없던 계좌」로 가른다.

### 해지가 막히는 계좌가 있다

예·적금·카드의 연결계좌이거나 **대출의 출금계좌**면 금융망이 거절한다(A1068·A1069·A1070).
우리가 풀 수 있는 조건이 아니라 그 계좌만 건너뛰고 나머지는 계속한다 — 로그에 왜 못 지웠는지
한 줄 남는다. 시연에서 대출을 신청해 본 계좌가 여기 걸린다.

**그리고 그 계좌는 다시 쓰지 않는다.** 「금융망 계좌 확보」가 재사용 대상에서 빼고 모자란
만큼 새로 만든다. 집어 가면 「금융망 잔액 맞추기」가 곡선이 원하는 금액으로 그 잔액을
옮기는데, 실제로 **대출 출금계좌가 6,442,803원에서 940,900원으로 깎였다**(2026-09-15).
그 계좌에 돈이 있어야 그 대출의 상환이 나간다. 계좌 하나 더 만드는 편이 싸다.

이때 **비웠던 돈은 도로 넣는다.** 못 지운 계좌를 빈 채로 두면 그 계좌를 출금계좌로 쓰는
대출의 상환이 조용히 실패한다. 되돌린 자국(`해지 전 잔액 정리`·`해지 취소 반환`)은
「잔액 맞추기 흔적 제외」가 찾는 적요에 함께 들어 있다 — 그 계좌를 다시 연동했을 때 동기화가
끌어와 매출로 읽히지 않게 하려는 것이다.

### 지우고 나서 멈추면 — 예보 화면이 옛 곡선을 보여준다

**계좌 0개 자체는 백엔드가 정식으로 다루는 상태다.** 재계산은 건너뛰고(`ForecastRunWorker`),
04:00 배치는 대상에서 빼고, 조회는 `422 FORECAST_INSUFFICIENT_DATA` 로 「연결된 계좌가 없다」를
알린다. 거기까지는 괜찮다.

**새는 곳은 저장된 실행이다.** 계좌 삭제는 `FORECAST_RUN` 을 지우지 않는데, 그 근거가
「재계산이 새 실행으로 덮는다」이다. 그런데 **마지막 계좌를 지우면 그 재계산이 건너뛰어져
덮을 것이 안 생긴다.** 조회는 완료된 실행을 먼저 찾으므로 422 가 아니라 **사라진 계좌로
계산된 옛 곡선을 그대로 200 으로 내려준다.**

시드가 끝까지 돌면 새 실행이 덮어 수 초짜리 창이다. 문제는 **중간에 멈췄을 때**다 — 1원
인증은 통장 적요에서 코드를 읽는 단계라 실제로 잘 깨진다. 그때 화면에는 없는 계좌의 잔액으로
그린 곡선이 떠 있고, **돈을 세는 화면이라 조용히 틀리는 쪽이다.**

그래서 **시드가 그 상태를 만들었으면 크게 경고한다.** 지우기가 비운 사업장에 계좌가 다시
섰는지 끝에서 확인하고, 안 섰으면 빨간 줄로 남긴다.

```
⚠ 계좌가 0개로 남았다 — 카페 한잔
  예보 화면은 빈 상태가 아니라 «사라진 계좌로 계산된 옛 곡선»을 그대로 보여준다.
```

세 자리에서 뜬다 — 실행이 **실패했을 때**, `--reset-only` 로 **일부러 멈췄을 때**, 화면에서
지우기만 골라 **끝났을 때**. 계좌가 다시 섰으면 조용하다. 시드를 끝까지 다시 돌리면 새 실행이
덮으면서 사라진다.

> 고칠 자리는 백엔드다(`ForecastQueryService#window` 가 저장된 실행을 찾기 **전에** 연결 계좌를
> 보면 된다). 여기서 막는 이유는 그 상태를 **만드는 쪽이 시드**여서다. 백엔드를 고치면 계좌를
> **해제만** 한 사업장까지 답이 200 에서 422 로 바뀌므로 팀이 따로 정할 일이다.

### 사업장은 안 지운다

계좌만 지운다. 상호가 같으면 「사업장 확보」가 그대로 재사용하므로 다시 세우는 데 문제가 없고,
사업장을 지우면 **거기 매달린 것까지 날아간다** — 휴무일과 상품별 매출 등록분이 그렇다.
거래가 딸려 오는 것은 계좌지 사업장이 아니다.

다만 그 둘은 **재실행이 덮어쓰지 못할 수도 있다.** 상품별 매출은 같은 기간이면 통째로
교체되지만(14.4) 기준일을 옮겨 창이 달라지면 지난 달치가 남고, 휴무일도 지난 실행에서 등록한
날짜가 그대로 있다. 시나리오를 크게 바꿨다면 그 둘은 화면에서 확인한다.

## 알아 둘 것

### 공백이 안 나오면 화면이 막는다

`solveOpening` 이 던지는 실패를 그대로 보여 준다. **공백 없는 시드는 시연이 안 되는 시드**라,
숫자만 찍고 넘어가면 발표 직전에야 알아차리게 된다.

```
2026-12-01 ~ 2026-12-31 안에 공백을 만들 수 없다 — 그 구간 저점이 163,000원이고
목표는 -250,000원이다.
```

이 시나리오의 공백은 **부가세 예정고지(1·4·7·10월 25일)와 급여 앞당김**에 기대고 있다.
그 사건이 창 안에 없으면 과거를 0 위로 유지한 채로는 마이너스를 만들 수 없다. 기준일을
옮기거나 앵커의 「며칠 안」을 늘린다.

### 금액을 고쳐도 공백은 안 사라진다

시작 잔액이 앵커에서 **역산**되기 때문이다. 임차료를 90만에서 150만으로 올리면 시작 잔액이
따라 올라가고 저점은 목표 근처에 남는다. 곡선의 수준이 아니라 **모양**을 고치는 것이 요점이다.

### 항목 표는 통째로 갈아 끼운다

`fixed` 와 `weekly` 는 화면이 보낸 키가 곧 있는 항목 전부다. 깊은 병합만 하면 **지운 항목이
기본값에서 되살아난다** — 고정비를 없애고 곡선을 맞췄는데 실제로 돌리면 그 돈이 그대로
나가는 것이라, 조용히 틀리는 쪽이다. 규칙은 `plan.mjs` 의 `REPLACING_TABLES` 에 있다.

수입 세 줄(`card`·`platform`·`cash`)은 늘리거나 줄일 수 없다. 난수 스트림이 그 이름에 매여
있어서, 이름을 바꾸면 6개월치 거래가 통째로 다른 값이 된다.

표를 새로 만들면 **`schema.mjs` 의 `TABLES` 에도 넣는다.** 서버가 그 목록만 돌면서 화면이
보낸 값을 받아들인다 — 빠뜨리면 화면에는 표가 보이는데 **고쳐도 아무 일이 안 일어난다.**
실제로 `irregular` 를 넣을 때 그렇게 한 번 조용히 무시됐다.

항목을 추가할 수 있는 표(`addable`)라면 **`newRow` 도 함께 둔다.** 화면에서 새로 만든 줄의
빈 칸을 그것으로 채운다 — 없으면 지출 항목 모양(금액·날짜·분류)이 들어가고, 상품 줄에는
단가가 없어 생성기가 그 줄을 그냥 건너뛴다.

### 주기 없는 거래 — 모델이 맞힐 몫

나머지 항목은 전부 주기가 있다. 그래서 백엔드 탐지기가 **예정 거래로 잡아가고**, 잡힌 만큼은
잔여에서 빠진다. 2026-09-13 실측에서 거래 290건 중 288건이 그렇게 설명됐고 잔여는 부가세
2건(금액의 2.3%)뿐이었다 — **예측 모델에 들어가는 입력이 사실상 비어 있었다.**

그래서 「예측할 수 없는 몫」을 일부러 만든다. 소모품·수리·환불·기프티콘 정산 네 줄이고,
각각 **다른 방식으로 탐지를 벗어난다.**

```
적요 흩뿌리기   거래처가 매번 달라 그룹마다 표본이 3건에 못 미친다   소모품
간격 흔들기     날짜가 무작위라 주기로 분류되지 않는다              카드 취소 · 기프티콘
드물게 일으키기 6개월에 몇 건이라 그룹이 서지 않는다                수리·AS
```

**하루 확률이 0 이면 그 항목은 안 만들어진다.** 네 줄을 다 0 으로 두면 이 표가 생기기
전의 시드와 같아진다(316건 · 저점 −273,600원).

항목을 화면에서 **늘릴 수는 없다.** 뜻을 모르고 하나 더하면 규칙적인 거래가 되어 탐지기가
그냥 잡아가므로 잔여가 늘지 않는다. 늘릴 일이 생기면 `scripts/seed/plan.mjs` 의 `irregular`
주석을 읽고 거기서 더한다. 잔여가 정말 남는지는
`private/현재/forecast-lab/audit/seed_residual.py` 가 잰다.

### 상품별 매출은 통장에서 나온다

시연에서 **상품별 매출(P1-22)은 등록 화면(SC-09-3)을 거치지 않는다.** 시드가 과거 달을
채운다(2026-09-15 결정). 그래서 구성비 조회·기간 추이와 리포트의 상품 기여도가 발표 첫
화면부터 값을 갖는다.

**금액을 따로 정하지 않는다.** 그 달의 총매출은 **매출성 입금(카드·배달·현금)을 채널
수수료로 되돌려** 환산한 값이고, 「상품 구성」 표가 정하는 것은 그 총액을 **어떻게 나눌지**
뿐이다. 판매 층을 따로 난수로 만들면 통장 합계와 인쇄물 합계가 서로 다른 매출을 말하게 된다 —
매출 금액의 단일 출처는 계좌 입금이라는 규칙(ERD 1.9 「소비처와 비소비처」)이 시드 안에서도
그대로여야 한다.

그래서 **인쇄물 총매출이 통장 입금보다 1할쯤 크다.** 정산 전과 정산 후의 차이이고(공통규약
1.5 「판매 · 정산 · 입금 3층」), 대부분이 배달 수수료다. 수수료율은 수입 표의 칸이다.

**창에 통째로 들어온 달만 만든다.** 인쇄물은 달이 끝나야 뽑고, 반달치를 넣으면 기간 추이에서
그 달만 반토막으로 보인다 — 구성비는 비율이라 멀쩡한데 조회 응답의 합계는 절대액이라 그렇다.
180일 창이면 대개 **다섯 달 · 65행**이 남는다. 무엇이 등록될지는 「거래 · 합계」 화면 아래쪽
인쇄물 미리보기에서 본다.

**월 변화가 시나리오를 만든다.** 전체 매출이 완만히 주는데 *무엇이 팔려서* 줄었는지가 이
기능이 답할 질문이라(SRS 7장), 딸기라떼를 계절 메뉴로 크게 빼고 아인슈페너를 신메뉴로 올려
뒀다. 전 품목을 고르게 두면 구성비가 다섯 달 내내 같은 그림이라 볼 것이 없다.

같은 기간을 다시 등록하면 서버가 **그 기간을 통째로 교체한다**(14.4). 몇 번을 돌려도 같다.

**출처(`sourceType`)는 전부 `MANUAL` 이다.** 스크립트가 직접 넣은 것이 사실이고, 이 칸이
있는 이유가 「어떻게 들어왔나」를 남기는 것이다.

한때 `OCR` 로 뒀다가 되돌렸다. "매달 인쇄물을 찍어 올려 왔다"로 보이게 하려던 것인데
**이 값은 어느 응답에도 안 나간다** — 14.4 등록 응답에도 14.5 구성비·추이에도 없어서 화면이
읽을 방법이 없다. 얻을 것이 없는 대신 잃을 것은 있었다: 이 스키마에서 `OCR` 은 **「모델이
읽은 그대로, 아무도 손대지 않았다」**는 뜻이라(14.6 이 사람 손이 닿은 행을 `OCR_CORRECTED`
로 올린다), 모델이 본 적 없는 65행이 그 버킷에 들어가면 나중에 **실사용 정확도가 거짓으로
오른다.**

### 고친 값은 그 탭에만 남는다

화면에서 맞춘 값은 `sessionStorage` 에 들어간다. **탭마다 따로**이고 탭을 닫으면 지워진다
(비밀번호가 섞이므로 그쪽이 낫다). 오래 두고 쓸 값은 「CSV · 설정 파일」에서 설정 파일로
내보낸다.

저장본은 **기본값 위에 얹는다.** 저장한 뒤에 새로 생긴 표·칸·단계는 기본값을 따르고, 고친
값과 지운 줄은 그대로 남는다. 그냥 통째로 쓰면 **나중에 생긴 표가 빈 채로 보인다** — 실제로
「상품 구성」을 넣은 날, 탭을 열어 둔 사람 화면에 머리글만 남고 13줄이 통째로 사라졌다
(2026-09-15). 서버를 다시 띄워도 안 고쳐진다. 저장본은 서버가 아니라 탭에 있다.

### 기준일을 미래로 두면

두 가지가 어긋난다. 리허설로 미리 돌릴 때 실제로 겪는 일이다.

1. 금융망 거래는 **실제 오늘** 날짜로 찍힌다(DD_09 에 날짜 파라미터가 없다). 잔액 맞추기
   '전기이월' 이 CSV 구간 한가운데 앉고, 그 행의 잔액만 곡선에서 튄다.
2. 거래 목록 기본 조회창이 `to = 오늘` 이라 CSV 의 뒷부분이 잘려 보인다.

발표 당일에 다시 돌리면 둘 다 사라진다.

### 날짜는 28일까지만

29~31 일은 없는 달이 있어, 그 달만 항목이 통째로 빠진다. 화면이 28 에서 자른다.

## 왜 서버가 있나

브라우저에서 금융망을 직접 부를 수 없고(`Origin` 이 붙으면 403), 곡선을 만드는 코드가
Node 모듈이라 그렇다. 덕분에 **apiKey 가 브라우저로 나가지 않는다** — 키는 이 프로세스에만
있고 화면에는 끝 4자리만 보인다.

그 밖에 지키는 것:

- `127.0.0.1` 에만 바인딩한다. `0.0.0.0` 으로 열면 같은 망의 누구나 팀 키로 계좌를 만진다.
- **`schema.mjs` 에 있는 경로만 설정으로 받는다.** 화면이 보낸 것을 통째로 믿고 생성기에
  넘기면 오타 하나가 6개월치 거래를 조용히 망가뜨린 채로 업로드된다. 타입대로 강제 변환하고
  범위를 벗어나면 자른다.
- 요청 본문을 로그에 남기지 않는다. 비밀번호와 토큰이 들어 있다. 로그에는 어느 단계를
  거쳤는지만 남는다.
- 「직접 넣기」는 토큰을 서버에 두지 않고 요청마다 로그인한다. 고른 계좌가 그 계정 것인지
  올리기 전에 다시 확인한다 — 화면이 준 id 를 그대로 믿지 않는다.
- 비밀번호를 `sessionStorage` 에 저장하지 않는다. 탭을 닫으면 지워진다.

## 스타일

`tools/fin-console` 과 같은 토큰·골격을 쓴다. 파일을 공유하지 않는 것은 각 서버가 자기
`public/` 만 내보내기 때문이다 — 공유하려면 빌드 단계가 생기고, 의존성 0개라는 성질을 잃는다.

우리 앱의 `sky.css`("하늘과 땅")를 따르지 않는다. 내부 개발 도구라 값이 잘 읽히는 쪽을 택했다.
다만 팀 규칙은 지킨다: 금액은 `1,340,000원` · 음수는 `−`(U+2212) · 한국어는 `keep-all` ·
**상태를 색만으로 구분하지 않는다**(곡선의 공백 구간은 색과 함께 빗금을 깔고, 저점에는
날짜와 금액을 글자로 붙인다).
