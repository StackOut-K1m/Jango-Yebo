# 금융망 콘솔

SSAFY 교육용 금융망(`finopenapi.ssafy.io`)을 화면에서 부르는 개발 도구.
`scripts/auth-code.mjs`·`scripts/fin-account.mjs` 를 매번 인자 바꿔 돌리던 일을 대신한다.

**개발 전용이다.** 배포 경로에 넣지 않고, 프론트엔드(`frontend/`)와도 분리해 둔다 —
빌드에 섞이면 팀 apiKey 를 다루는 코드가 배포 산출물에 들어간다.

## 실행

```bash
npm run fin
```

`http://127.0.0.1:5180` 이 열린다. 포트를 바꾸려면 `PORT=6000 npm run fin`.

의존성이 없다. `node:http` 와 전역 `fetch` 만 쓰므로 설치 과정이 없다(Node 18+).

## 무엇을 준비해야 하나

`backend/.env` 의 `FINOPENAPI_API_KEY` 하나면 된다. 이미 백엔드를 돌리고 있다면 그대로 쓰인다.

| 값                            | 출처                      | 없으면                                       |
| ----------------------------- | ------------------------- | -------------------------------------------- |
| `FINOPENAPI_API_KEY`          | `backend/.env`            | 화면이 안내만 띄우고 아무 호출도 하지 않는다 |
| `FINOPENAPI_BASE_URL`         | `backend/.env`            | `https://finopenapi.ssafy.io`                |
| `FINOPENAPI_INSTITUTION_CODE` | `backend/.env`            | `00100`                                      |
| `FINOPENAPI_FINTECH_APP_NO`   | `backend/.env`            | `001`                                        |
| `SEED_USERKEY_*`              | `backend/.env.seed.local` | 시드 계정 단추만 안 보인다                   |

`process.env` 가 파일보다 우선한다. 저장소 밖에서 띄운다면 `JANGO_REPO` 로 저장소 경로를 준다.

## 왜 프록시가 있나

브라우저에서 금융망을 직접 부를 수 없다. `Origin` 이 붙으면 403 `Invalid CORS request` 다(실측).
그래서 이 프로세스가 대신 부른다.

덕분에 **apiKey 가 브라우저로 나가지 않는다.** 키는 이 프로세스에만 있고 화면에는 끝 4자리만 보인다.
시드 `userKey` 도 이름(`SEED_USERKEY_OWNER`)만 오가고 값은 서버가 채운다.

그 밖에 지키는 것:

- `127.0.0.1` 에만 바인딩한다. `0.0.0.0` 으로 열면 같은 망의 누구나 팀 키로 계좌를 만진다.
- `catalog.mjs` 에 있는 인터페이스만 부른다. 경로를 화면에서 받지 않는다 — 오타 한 번이
  "서버가 죽었나"로 번지고(없는 경로는 404 에 응답 형태까지 다르다), 금지 인터페이스를 막을 수 없다.
- 요청 본문을 로그에 남기지 않는다. `Header` 에 `apiKey` 와 `userKey` 가 들어 있고
  `userKey` 는 사실상 계좌 접근권이다. 로그에는 어느 인터페이스를 불렀는지만 남는다.
- 응답에 되비치는 요청 사본에서 `apiKey` 를 가린다.

## 명세가 바뀌면

`public/catalog.mjs` 한 파일만 고친다. 서버와 브라우저가 같은 파일을 읽으므로 폼과 요청 조립이
함께 따라온다. 출처는 `SSAFY_교육용_금융망_API_Inferface_예제.xlsx`(173시트)다.

목록 화면은 렌더러를 새로 짜지 않는다. `render: 'table'` 에 `columns` 를 적으면 된다:

```js
render: 'table',
listKey: 'reservations',   // 2026년 계열은 REC 밑 이름 붙은 키에 목록이 있다
columns: [
  col('reservationName', '이름'),
  col('transactionBalance', '금액', { money: true, right: true }),
  col('status', '상태', { badge: true }),
],
rowTo: { id: 'TRANSFER_RESERVATION_02', field: 'reservationId' },  // 행 클릭 → 다음 화면
```

`money`·`date`·`datetime`·`rate`·`bool`·`badge`·`mono` 가 표기를 정한다. 필드 이름이
`FIELD_LABEL`·`MONEY_FIELDS` 같은 표에 있으면 낱값 화면(`record`)에서도 같게 나온다.

## 알아 둘 것

- 개발·시연 계좌는 **싸피은행(999)** 에 만든다. 실제 은행망과 무관한 가상 은행이다.
- 금액뿐 아니라 **기간·금리·한도까지 전부 문자열**로 보낸다. 워크북 표에는 `Long`·`int`·`double`
  로 적혀 있지만 요청 예제는 모두 따옴표가 붙어 있고, 숫자로 보내면 `Q1001` 이다.
  예외는 `Boolean` 둘뿐이다(`autoTransfer`·`unreadOnly`).
- 입금·출금 API 에 **날짜 파라미터가 없다.** 무조건 오늘 거래로 남는다 — 과거 이력은
  시드 스크립트가 만드는 CSV 업로드가 담당한다.
- 이메일 하나로 `userKey` 가 정해진다. 백엔드(`FinUserKeyService`)도 같은 방식으로 찾으므로,
  여기서 만든 계좌는 **같은 이메일로 앱에 가입한 사용자**의 것이 된다.

### 금융망 스케줄러가 잔고를 바꾼다

전부 한국시간이다. 발표 전날 시드를 다시 돌려 상태를 고정하는 이유다.

| 시각      | 작업                                        |
| --------- | ------------------------------------------- |
| 00:00     | 마이너스통장 이자 발생                      |
| 00:10     | 마이너스통장 납입·연체 판정                 |
| **08:30** | **대출 상환 — 매일**                        |
| 09:00     | 예약이체 실패분 재실행 (당일 재시도는 없다) |

**대출 상환이 매일이다.** 개설 다음날부터 매일 `(대출금 + 이자) / 대출기간` 이 출금 계좌에서
빠진다. 목업은 「9월 10일 대출 상환 1,680,000원」처럼 월 1회 큰 금액으로 그렸는데, 금융망에서는
매일 소액이라 **예보 곡선 모양이 다르다** — 월 1회면 절벽, 매일이면 완만한 우하향이다
(기술스택 12장 미결).

`LOAN_09` 의 `failureReason` 에 **"자동이체 실패 잔액 부족"** 이 그대로 온다. 잔액을 상환액
아래로 떨어뜨려 놓고 08:30 을 지나면 실패 이력이 생긴다 — 우리 서비스의 핵심 장면을 금융망이
실제로 재현한다.

> `LOAN_09` 예제의 `repaymentAttemptTime` 은 `080030`(08:00:30)인데 플로우 문서는 08:30 이라고
> 한다. 스케줄러를 명시한 쪽이 플로우 문서라 08:30 으로 적었다 — 실제 대출을 하나 만들어 보면
> 확정된다.

### 금리는 연이율이다 — 이자는 한 번만 계산된다

`LOAN_02` 응답의 `repaymentMethodTypeName` 은 **원리금균등상환**이라고 온다. 그런데 실제 산출식은
잔액이 줄면 이자도 줄어드는 분할상환이 아니다(`LOAN_09` 시트):

```
이자     = 원금 × (금리 / 100) × (대출기간 / 365)      ← 반올림, 한 번만
loanBalance = 원금 + 이자                              ← 가입 순간 확정
하루치   = loanBalance / 대출기간                       ← 매일 같은 금액
```

**처음 원금에 전 기간 단리**를 한 번 계산해 총액을 확정한 뒤 일수로 나눈다. 워크북 `LOAN_09`
예제가 그대로 맞는다 — `loanBalance` 120,000,000 / 5일 = 1회차 24,000,000, 남은 96,000,000.

우리 예측 엔진에는 이게 편하다. 상환 일정을 분할상환표로 전개할 필요 없이 **상수 하나**이므로,
`PLANNED_TRANSACTION(source_type = LOAN)` 생성 규칙이 그만큼 단순해진다.

**연이율이라는 걸 놓치면 이자를 12배로 읽는다.** 30일 대출에 금리 `5` 는 5%가 아니라
`5 × 30/365 ≈ 0.41%` 다. 콘솔의 `대출 받기` 묶음이 상품마다 이 값을 계산해서 보여준다.

- 금리 범위 0.1~~20%, **소수점 가능**. 대출 기간 2~~365일, 금액 1,000원~3억원.
- 상환이 끝나면 대출 계좌는 **자동 해지**된다. 단 한 번이라도 연체가 있었으면 연체금을 낼 때까지
  계좌가 남는다.
- 마이너스통장 이자도 연이율이지만 **사용한 금액에만 매일 00:00** 에 붙는다. 워크북에 산출식이
  없어 예제로 검산했다 — `100,000 × 0.045 / 365 = 12.33` → `dailyInterest: 12`. 문서 근거가
  아니라 추정이다.

### 대출과 마이너스통장은 규칙이 다르다

`LOAN` 하나로 둘을 담지 않는다(기술스택 4.13).

|      | 대출 `LOAN_*`                        | 마이너스통장 `MINUS_ACCOUNT_*`                          |
| ---- | ------------------------------------ | ------------------------------------------------------- |
| 기간 | **2~365일**                          | **12·24·36개월**                                        |
| 상환 | **매일 08:30**, `(대출금+이자)/기간` | 이자 납입일·자동 상환일 **매월 01~28일**                |
| 상태 | 개설 · 상환중 · 연체                 | `NORMAL` · `OVERDUE` · `CLOSED`                         |
| 알림 | 없음                                 | `MINUS_ACCOUNT_10` — 3일 전 예정 · 연체 · 연체 3일 경고 |

`MINUS_ACCOUNT_10` 의 알림은 우리 `ALERT` 와 겹친다. 도입 시 `dedup_key` 규칙을 먼저 정한다.

### 신용등급을 실제 신용등급처럼 보이게 하지 않는다

`LOAN_04` 는 **자산 합계로만** 등급을 낸다 — 수시입출금 + 예·적금 잔액이 전부고 연체 이력도
소득도 반영되지 않는다. 그래서 이 콘솔도 등급 옆에 "보유 자산 기준 참고 등급"을 붙인다.
제품 화면도 같은 표기를 쓴다(기술스택 4.13 · API 16장 `gradeBasis`).
